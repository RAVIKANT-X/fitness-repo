A. Current Frontend Structure

Routing (App.tsx)

  • / → HomePage — welcome banner + stats placeholder grid
  • /exercises → ExerciseSelectionPage — pick exercise, navigate to /workout
  • /workout → LiveWorkoutPage — camera + MediaPipe + analysis engine + inline session summary
  • /session-summary → SessionSummaryPage — standalone placeholder page (unused in live flow)
  • /progress → ProgressPage — history placeholder
  • /profile → ProfilePage — settings placeholder

Shell (Layout.tsx)

  • Sticky header (brand + centred page title)
  • Scrollable main content area with pb-24 bottom padding
  • Fixed BottomNav — hidden at md+ breakpoint

Shared Components

  • Button — primary / secondary / outline, sm/md/lg, fullWidth
  • Card — white surface, rounded-card (1rem), shadow, optional elevated
  • BottomNav — 4 items: Home, Exercises, Progress, Profile. NavLink active state.
  • CameraView — <video> with status states, mirror transform, children slot for canvas
  • PoseOverlay — <canvas> skeleton renderer, mediapipe inference loop
  • WorkoutFeedback — reps / phase / form / angles / deviations (purely presentational)

State / Hooks

  • useSelectedExercise — React Context, exercise shared between ExerciseSelection → LiveWorkout
  • useCamera — camera stream lifecycle
  • usePoseLandmarker — MediaPipe model + inference loop
  • useAnalysis — bridges analysis engine to React

Key Observations

The session summary UI currently lives inside LiveWorkoutPage as an inline component — not in /session-summary. The SessionSummaryPage at /session-summary is a Phase 1 placeholder that is never navigated to by the real flow.
There is no Exercise Details page — users go directly from exercise list → workout camera. This is the gap we are filling.

D. Proposed Exercise-Detail Data Model

Extended ExerciseDefinition

We extend the existing ExerciseDefinition interface in exerciseTypes.ts with optional educational fields only. All existing biomechanics fields (primaryAngles, requiredLandmarks) remain completely unchanged.

// Additions to ExerciseDefinition (all optional — no breaking change)

shortDescription: string       // 1-sentence hero text for Detail page
difficulty: 'beginner' | 'intermediate' | 'advanced'
category: string               'Strength' | 'Mobility' | 'Cardio'

instructions: string[]         // Ordered steps for "How to perform"
commonMistakes: string[]       // What to avoid — shown in Detail page
aiMonitors: string[]           // What the AI checks — listed in Detail page

// Already exists — keep unchanged:
description: string            // card subtitle (one sentence)
muscleGroups: string[]         // tag pills
primaryAngles: AngleDefinition[]
requiredLandmarks: PoseLandmark[]

All content lives in exerciseLibrary.ts per exercise. The ExerciseDetailPage simply reads from the definition — no hard-coded strings in the UI.

Example — Squat

FieldValue
shortDescription"A foundational lower-body movement that builds strength in your quads, glutes, and core."
difficultybeginner
categoryStrength
instructions1. Stand feet shoulder-width apart… 2. Brace your core… 3. Bend knees… 4. Lower until thighs parallel… 5. Push through feet to stand
commonMistakes["Knees caving inward", "Shallow depth", "Rounding the lower back", "Heels lifting off the floor"]
aiMonitors["Knee angle (left & right)", "Hip angle", "Left/right knee symmetry", "Squat depth"]

  • Card radius: rounded-card = 1rem — existing, kept
  • Button radius: rounded-xl (12px) for primary, rounded-lg for secondary — existing, kept

  • Section gap: space-y-5 or space-y-6 — consistent with existing

Exercise Card Visual Language

Each exercise card gets a distinct colour accent and a simple CSS illustration (no external images). The icon badge grows from 44px → 60px. Cards include: name, short description, difficulty pill, muscle group tags, and a "View Details →" CTA.

  • Squat: warm green accent, lower-body icon
  • Push-Up: blue accent, upper-body icon
  • Curl: amber accent, arm icon

Live Workout Layout

Camera takes full-width, 3:4 portrait ratio on mobile. Feedback panel sits below the camera in a compact horizontal strip rather than stacked cards. Controls (Finish, Switch Camera) pinned at the bottom. On desktop the camera and feedback sit side-by-side.

F. Proposed Responsive Strategy

BreakpointWidthStrategy
Mobile (default) 360–430px Single column, bottom nav, camera full-width 3:4, feedback below camera
Tablet (sm: 640px) 640–1023px Camera switches to 16:9, exercise cards become 2-col grid
Desktop (md: 1024px+) 1024px+ Bottom nav hidden; sidebar nav added to Layout; workout page 2-col (camera left, feedback right); max-width 1024px centred
The existing Layout.tsx already has max-w-screen-lg mx-auto and md:hidden on BottomNav. We keep this strategy and add a desktop sidebar nav in the Layout shell rather than stretching the mobile layout.
