5. Ghost Synchronization Implementation

Phase-based synchronisation (ghostSync.ts)

  • Ghost pose resolved from user's current MovementPhase — not an independent timer
  • Phase ordering defined per exercise: STANDING→DESCENDING→BOTTOM→ASCENDING etc.
  • phaseProgress (0–1) interpolates smoothly between current and next phase reference
  • Temporal smoothing via EMA (α=0.35) prevents snapping/jitter
  • prevGhostRef resets on phase or exercise change

Body-relative accuracy (adaptReferenceToUser)

  • Body frame computed from shoulder + hip landmarks (4 anchor points)
  • Reference rescaled to match user's shoulder width (hw) and torso height (th)
  • Ghost shifts to user's cx/cy — stays aligned regardless of position in frame
  • Scale factor also applied to landmark radius and line width

6. Ghost Visibility (≈1 meter)

  • Base landmark radius: 8px (was 5px) — scales with body size in frame
  • Connection width: 3.5px (was 2.5px) — thicker, clearly visible lines
  • White border ring (2px) on each landmark dot — contrast on any background
  • Ghost colour: emerald-400 at 65% opacity (was green at 55%) — more distinct
  • Body scale factor: torsoHeightPx/200 — larger body → larger markers
  • Scale range: 0.6× to 2.0× — prevents over/undersizing
  • "TRUE REFERENCE" label drawn near ghost head (pill badge, green background)
  • Opacity: 0.70 in LiveWorkoutPage (was 0.65)

7. Human Detection Implementation

  • Uses MediaPipe landmark visibility scores — no additional model
  • Dogs, furniture, empty rooms → no landmarks → NO_PERSON state
  • Torso visibility check: ≥4 of [11,12,23,24] required at vis≥0.45
  • Exercise-specific check: squat needs legs, pushup needs arms, etc.
  • Average visibility check: <0.25 → LOW_CONFIDENCE
  • LiveWorkoutPage shows human-friendly message from humanDetection.message
  • "Step into frame to begin." when no pose detected
  • Ghost hidden until humanValid OR personVisible (allows partial tolerance)

9. Progress / Streak Implementation

Score System (transparent, data-driven)

  • Form Quality: % of GOOD-form sessions (45% weight)
  • Consistency: active days in last 7 / 7 (35% weight)
  • Progress: recent avg reps vs earlier avg reps (20% weight)
  • Score ring SVG with dynamic green/amber/red based on value
  • Requires ≥2 sessions; shows "needs more data" honestly

Streak System

  • Current streak counted backwards from today (calendar days)
  • Best streak computed from sorted unique session days
  • Multiple sessions on same day counted once
  • Daily activity grid (Mon–Sun, current week)
  • "Train today" motivation when streak is 0

Exercise Performance

  • Per-exercise good form % with gradient progress bars
  • Session count + total reps per exercise
  • Top 5 exercises by session count

Insights

  • Data-driven only — no fabricated AI statements
  • "Complete more sessions" when insufficient data (<4 sessions)

12. Remaining Limitations

  • Specialist phone numbers: All 4 entries use demo placeholders. Replace in specialistConfig.ts before production.
  • Actual movement capture: The "capture exact mistake frame as user photo" feature was not implemented — requires canvas capture + privacy consideration. Reference landmark snapshots already stored in ReferenceComparison.userLandmarkSnapshot.
  • Streak persistence: Streak is computed client-side from backend session records on every load. No separate streak table — relies on session backend being reachable. Offline sessions are not counted.
  • phaseProgress estimation: Phase progress (0–1) uses a default of 0.5 in LiveWorkoutPage. A more precise angle-based estimator per exercise would further improve ghost interpolation accuracy.
  • Reference images: No external image URLs are used anywhere — all reference visuals are landmark-based canvas renders. Real reference photography would require asset hosting.
  • Multiple person detection: MediaPipe may detect a person near a mirror or mannequin. The MULTIPLE_PERSONS state is not surfaced in the UI (landmark count check not implemented).
